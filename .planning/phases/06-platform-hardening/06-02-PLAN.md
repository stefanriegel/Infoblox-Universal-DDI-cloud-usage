   - Change `-Subject "CN=Infoblox Universal DDI Setup"` to `-Subject "CN=Infoblox UDDI Estimator"`
   - Change `-NotAfter (Get-Date).AddYears(1)` to `-NotAfter (Get-Date).AddYears(2)`

2. **Keep everything else unchanged** — the workflow structure, signing, verification, and commit steps are correct. The `[skip ci]` in the commit message prevents infinite loops per Pitfall 6 in RESEARCH.md.

3. **Ensure paths filter is preserved** — the existing `paths: ['setup_venv.ps1']` filter ensures the workflow only triggers when the PS1 file changes. This is correct.

The complete "Create self-signed certificate" step should become:
```powershell
Write-Host "Creating self-signed code signing certificate..."
$cert = New-SelfSignedCertificate -Subject "CN=Infoblox UDDI Estimator" `
  -Type CodeSigningCert -CertStoreLocation Cert:\CurrentUser\My `
  -HashAlgorithm sha256 `
  -NotAfter (Get-Date).AddYears(2)
Write-Host "Certificate created with thumbprint: $($cert.Thumbprint)"
```
Note: Add `-HashAlgorithm sha256` explicitly (best practice for code signing). The existing cert export, thumbprint save, and trusted root import steps remain unchanged.

**Create `docs/enterprise-resign.md`:**

Create the enterprise re-signing guide per CONTEXT.md decision "Document how customers can re-sign scripts with their own enterprise certificate". The document should cover:

1. **Overview** — why re-signing is needed (self-signed certs are not trusted by default; enterprise IT requires their own cert chain)

2. **Prerequisites** — a code signing certificate issued by the enterprise's internal CA (or a commercial CA), with the certificate in `Cert:\CurrentUser\My`

3. **Re-signing steps:**
   ```powershell
   # 1. Find your enterprise code signing certificate
   Get-ChildItem Cert:\CurrentUser\My -CodeSigningCert

   # 2. Sign the script with your certificate
   $cert = Get-ChildItem Cert:\CurrentUser\My -CodeSigningCert | Where-Object { $_.Subject -like "*YourCompany*" }
   Set-AuthenticodeSignature -FilePath setup_venv.ps1 -Certificate $cert

   # 3. Verify the signature
   Get-AuthenticodeSignature -FilePath setup_venv.ps1
   ```

4. **Distributing the re-signed script** — place the re-signed `setup_venv.ps1` in the tool directory; the enterprise CA is already trusted on domain machines, so no cert import is needed

5. **Using the self-signed cert** (for non-enterprise environments) — import `cert.cer` to trusted root:
   ```powershell
   # Requires admin elevation
   Import-Certificate -FilePath .\cert.cer -CertStoreLocation Cert:\LocalMachine\Root
   ```

6. **Troubleshooting** — common errors: "The signature of the certificate cannot be verified" (cert not in trusted root), "Script cannot be loaded because running scripts is disabled" (ExecutionPolicy is Restricted — see setup warnings), GPO-enforced policies (contact IT admin)

Keep the document concise (60-80 lines). Use PowerShell code blocks. Reference `setup_venv.ps1` and `cert.cer` by name. Do not use emojis.
