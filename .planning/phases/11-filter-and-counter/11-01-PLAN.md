<feature>
  <name>nios.filter — FilterConfig + filter_objects()</name>
  <files>src/cloud_usage/nios/filter.py, tests/nios/test_nios_filter.py</files>
  <behavior>
    FILTER-01 — Whitelist passes matching members:
    - filter_objects() with config.whitelist=("gm*",) passes objects where
      member_hostname matches "gm*" (e.g., "gm-member-01.corp.example.com")
    - Objects with non-matching member_hostname (e.g., "ns1.example.com") are dropped
    - test name: test_whitelist_passes_matching_members

    FILTER-01 — Grid-level objects always pass:
    - Objects with member_hostname=None pass through regardless of whitelist/blacklist
    - This is unconditional — not gated on whether whitelist is non-empty
    - test name: test_grid_level_always_passes

    FILTER-02 — Blacklist excludes matching members:
    - config.blacklist=("ns1.*",) drops objects where member_hostname matches "ns1.*"
    - Non-matching members still pass through
    - test name: test_blacklist_excludes_matching_members

    FILTER-03 — Whitelist-first semantics:
    - config.whitelist=("gm*",), config.blacklist=("gm*",): whitelist admits "gm-01",
      then blacklist tries to exclude — result: "gm-01" is excluded (blacklist wins on
      the whitelist-admitted set, NOT that whitelist prevents blacklist from running)
    - The whitelist-first rule means: start with whitelist set, THEN apply blacklist to that set
    - If whitelist is empty, all members start as admitted; blacklist then excludes from the full set
    - test name: test_whitelist_first_semantics

    FILTER-04 — Zero-match whitelist emits warning:
    - config.whitelist=("no-match-pattern-*",) matches no member_hostname in stream
    - After stream exhaustion, logging.warning() is called with the non-matching pattern
    - Grid-level objects (member_hostname=None) still pass through even when zero match
    - test name: test_zero_match_whitelist_warns

    Additional behaviors:
    - Empty whitelist (config.whitelist=()) means no whitelist filtering — all members pass
    - Empty blacklist (config.blacklist=()) means no blacklist filtering
    - FilterConfig.lease_states is included for completeness but unused in filter.py
      (used only by counter.py) — present in FilterConfig as shared config object
    - test name: test_empty_whitelist_passes_all, test_empty_blacklist_passes_all
  </behavior>
  <implementation>
    FilterConfig is a frozen dataclass with tuple fields (not list — enforces true immutability
    for a config object, and avoids the list-mutation issue on frozen dataclasses):
    ```python
    @dataclass(frozen=True)
    class FilterConfig:
        whitelist: tuple[str, ...]       # default: ()
        blacklist: tuple[str, ...]       # default: ()
        lease_states: tuple[str, ...]    # default: ("active", "static")
    ```

    filter_objects() is a lazy generator that:
    1. For each obj in objects:
       - If obj.member_hostname is None: yield immediately (grid-level pass-through)
       - If whitelist is non-empty: check fnmatch.fnmatch(hostname, p) for each pattern;
         if no pattern matches, skip (continue)
       - If blacklist is non-empty: check fnmatch.fnmatch(hostname, p) for each pattern;
         if any matches, skip (continue)
       - Otherwise: track matched hostname in a local set, yield obj
    2. After the loop: for each whitelist pattern, if no matched hostname matches it,
       call _logger.warning("Whitelist pattern %r matched no members in backup", p)

    Use fnmatch.fnmatch() (not fnmatchcase) — DNS hostnames are case-insensitive by RFC;
    the default normcase behaviour is correct.

    Module-level logger: `_logger = logging.getLogger(__name__)`

    Module structure:
    ```
    src/cloud_usage/nios/filter.py
    ├── imports: __future__.annotations, dataclasses, fnmatch, logging, typing.Iterator
    ├── import: cloud_usage.nios.schema.NiosObject
    ├── FilterConfig dataclass (frozen=True)
    ├── _logger = logging.getLogger(__name__)
    └── filter_objects() generator function
    ```
