  <action>
    Wire all GCP collectors into discover_account() and create end-to-end integration tests.

    **src/cloud_usage/providers/gcp/provider.py**: Update discover_account() from skeleton to fully wired.
    - Import all collector functions from collectors/ subpackage.
    - Order of collection (no strict dependency ordering needed for GCP unlike Azure VNets):
      1. DDI: VPCs (global list), Subnets (aggregatedList)
      2. DNS: Zones (per-project dns.Client), Records (per zone, dependency on zones list)
      3. Compute: VMs (aggregatedList), Forwarding Rules (aggregatedList)
      4. Networking: Reserved IPs (aggregatedList + global)
      5. Database: Cloud SQL (discovery API)
      6. Token-free: Disks, Instance Groups, GKE Clusters, URL Maps, Storage Buckets
    - Create per-project DNS client inside discover_account: `dns.Client(project=account_id, credentials=self._credentials)`. Wrap in try/except ImportError for graceful handling when google-cloud-dns not installed.
    - Use _safe_collect for every collector call (error isolation per resource type).
    - DNS records depend on DNS zones (pass zones list to collect_gcp_dns_records).
    - Storage buckets collector takes credentials + project_id (not a shared client).
    - Check ProjectInfo API enablement flags:
      - If project's compute_enabled is False, skip compute-dependent collectors (VMs, disks, instance groups, forwarding rules, subnets, reserved IPs, URL maps).
      - If project's dns_enabled is False, skip DNS collectors (zones, records).
      - If project's sqladmin_enabled is False, skip Cloud SQL collector.
      - If project's container_enabled is False, skip GKE cluster collector.
      - To implement this: store ProjectInfo list in provider constructor, build a project_id -> ProjectInfo lookup dict. In discover_account, look up the project's API enablement flags.
    - Log summary: "Discovered {N} resources in project {project_id}" at end.

    **tests/test_integration_gcp.py**: End-to-end integration tests.
    Mock all GCP SDK clients and test the full pipeline: discovery -> counting -> tokenization -> output.

    Test cases:
    1. **Full pipeline test**: Mock all collectors returning representative resources. Run through the full CLI counting pipeline (fold_enis -> exclude_managed -> dedup -> categorize -> count_ips -> calculate_tokens). Verify token calculation is correct.
    2. **Token-free exclusion test**: Include gcp-disk, gcp-gke-cluster, gcp-instance-group resources. Verify they are categorized as token-free with correct skip_reasons and counted=False.
    3. **DDI counting test**: Include gcp-vpc, gcp-subnet, gcp-dns-zone, gcp-dns-record resources. Verify they are categorized as DDI with counted=True.
    4. **IP deduplication test**: Create resources with overlapping IPs in same project. Verify per-VPC IP dedup works correctly for GCP (account_id-scoped since GCP doesn't have VPCs as IP spaces like AWS).
    5. **Multi-project test**: Simulate 3 projects with different resource mixes. Verify per-project token summaries and provider totals.
    6. **Partial failure test**: Mock one collector to raise exception. Verify _safe_collect catches it, other collectors still run, and results are correct for successful collectors.
    7. **API disabled skip test**: Set compute_enabled=False on a project. Verify compute collectors are skipped but DNS still runs.
    8. **Output generation test**: Run full pipeline and verify XLS report is generated with correct content (use openpyxl to read back).
    9. **Checkpoint resume test**: Mock checkpoint with one project completed. Verify that project is skipped on resume.
    10. **Empty project test**: Project with no resources. Verify empty list returned, no errors.

    Pattern: Follow `tests/test_integration_azure.py` structure but adapted for GCP. Use unittest.mock to mock all GCP SDK clients. Create helper functions to build mock resources.

    Target: ~10-12 integration tests.
