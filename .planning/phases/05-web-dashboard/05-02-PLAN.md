    Implement the HTMX HATEOAS tab pattern and SSE progress streaming:

    1. **templates/partials/tab_bar.html** -- HTMX tab bar per Research Pattern 3:
       - Three tabs: Progress, Results, Summary
       - Each tab is an `<a>` with `hx-get="/tab/{name}" hx-target="#tab-container" hx-push-url="false"`
       - Active tab has CSS class `tab-active` (underline accent per locked decision)
       - Tab badges per locked decision: "Progress (scanning...)" or "Progress (idle)", "Results (N)" showing resource count, "Summary"
       - Template receives `active_tab` and `scan_state` and `resource_count` variables
       - Use Pico CSS `<nav>` with role="tablist" for semantic HTML

    2. **templates/pages/progress.html** -- Progress tab full content:
       - Extends or includes tab_bar.html within a wrapper div#tab-container
       - SSE connection: `<div hx-ext="sse" sse-connect="/api/sse/progress" id="progress-container">`
       - Per-provider rows: for each active provider, render a progress_row.html partial
       - Each row has `sse-swap="progress_{provider_lower}"` to receive SSE updates
       - Include an expandable section per provider for per-account details (collapsed by default per locked decision)
       - Show "No scan running" message when ScanManager state is IDLE
       - Show completion banner when state is COMPLETE: "Scan complete: N resources across M providers" per locked decision
       - Cancel button visible during scan per locked decision: `<button hx-post="/api/scan/cancel" hx-swap="none">Cancel</button>` (disabled when not running)

    3. **templates/partials/progress_row.html** -- Single provider progress row:
       - Provider name, progress bar (`<progress value="completed" max="total">`), "N/M accounts" text, current status
       - Warning indicator for errors: yellow/red marker per locked decision
       - This partial is swapped by SSE events -- each SSE event for `progress_aws` sends this rendered HTML
       - Expandable detail area for per-account status (toggled via HTMX or minimal CSS class toggle)

    4. **templates/components/error_banner.html** -- Reusable success/error banner:
       - Accepts `message`, `type` (success/warning/error)
       - Success: green background, auto-dismiss after 5 seconds via HTMX `hx-trigger="load delay:5s" hx-get="/partials/empty" hx-swap="outerHTML"`
       - Warning/error: yellow/red with persistent display

    5. **routes/sse.py** -- SSE streaming endpoint per Research Pattern:
       - `GET /api/sse/progress` -- returns `StreamingResponse` with `media_type="text/event-stream"` and headers `Cache-Control: no-cache`, `Connection: keep-alive`, `X-Accel-Buffering: no` (Pitfall 3)
       - Inner `event_generator()`: subscribes to EventBridge, for each event renders the appropriate progress_row.html partial as HTML, yields as SSE `event: progress_{provider}\ndata: {html}\n\n`
       - Check `request.is_disconnected()` per Research Pattern to stop on client disconnect
       - For `scan_complete` event type: yield a completion event that the client handles (e.g., triggers tab switch via HX-Trigger header pattern, or renders a success banner)
       - Register router in app.py

       **IMPORTANT SSE data format decision:** SSE events carry rendered HTML (not JSON) so HTMX `sse-swap` can directly swap the content. The route renders `progress_row.html` with updated data and sends it as the SSE data field. Multi-line HTML must be serialized as a single `data:` field (newlines replaced, or use JSON-wrapped HTML). Simpler approach: use JSON data with HTMX's `hx-vals` or render compact single-line HTML. Recommended: send JSON `{"completed": N, "total": M, "resources": R, "status": "..."}` and use `sse-swap` with an `<template>` approach, OR render server-side HTML and encode as JSON string in data field. Choose whichever is simpler -- the key is that the progress bars update in real time.

    6. **routes/pages.py** -- Update to serve tab-based pages:
       - `GET /` -- redirect to `/tab/progress` or render progress tab as default
       - `GET /tab/progress` -- render tab_bar + progress page content, pass `active_tab="progress"` and scan state
       - `GET /tab/results` -- render tab_bar + placeholder "Results will appear after scan completes" (Plan 03 fills this in)
       - `GET /tab/summary` -- render tab_bar + placeholder "Summary will appear after scan completes" (Plan 03 fills this in)
       - Each tab endpoint returns the full `#tab-container` div (tab bar + content) for HTMX swap

    7. **base.html** -- Update to wrap main content in `<div id="tab-container">` and set up initial tab load via `hx-get="/tab/progress" hx-trigger="load" hx-target="#tab-container"` on the main content div.

    8. **app.css** -- Add/update tab bar styling, progress row styling, and expandable section styles.

    9. **app.py** -- Register the SSE router: `app.include_router(sse_router)` from routes/sse.py.
