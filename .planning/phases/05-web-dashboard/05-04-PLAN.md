       - `POST /api/scan/start` -- validate `scan_manager.can_start()` (return 409 if already running per Pitfall 4), build ScanConfig, save config via `scan_manager.save_scan_config()`, kick off scan pipeline in background thread via `asyncio.get_running_loop().run_in_executor(None, _run_scan_pipeline, ...)` per Research Pattern.        **Scan Pipeline (_run_scan_pipeline function):**
       - Set scan_manager state to RUNNING
       - Build discovery providers from ScanConfig (reuse `_get_discovery_providers` logic from cli.py -- import or extract to shared utility)
       - Create DashboardProgressTracker(event_bridge) instead of plain ProgressTracker
       - Create DiscoveryOrchestrator with DashboardProgressTracker

       - Store resources, errors, output_paths in scan_manager
       - Set state to COMPLETE (or ERROR on exception)
       - Call event_bridge.emit_done() via DashboardProgressTracker.finish()

       **CRITICAL per Pitfall 2:** Never call blocking SDK methods in async route handlers. All blocking work (auth check, account enumeration, scan pipeline) runs via `asyncio.to_thread()` or `run_in_executor()`.

       **Cancel:**
       - `POST /api/scan/cancel` -- set scan_manager state to CANCELLED, trigger GracefulShutdown flag (need to pass shutdown handler reference). Return confirmation. Show "Cancelling..." state per Pitfall 7.

       - On scan start, save config via `scan_manager.save_scan_config()`.
