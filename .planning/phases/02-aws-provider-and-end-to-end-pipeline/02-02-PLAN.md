  <behavior>
    **categorizer.py** - categorize_resources(resources: list[CloudResource]) -> list[CloudResource]:
    - DDI resource types: "vpc", "subnet", "route53-zone", "route53-record", "dhcp-option-set"
    - IP category: resources with IPs that are not DDI and not token-free
    - Asset category: resources with IPs that qualify as managed assets (EC2, RDS, ELB, etc.)
    - Token-free types (discovered, skipped): "ebs-volume" -> skip_reason="token-free: EBS Volume", "s3-bucket" -> skip_reason="token-free: S3 Bucket"
    - DHCP option sets with details["orphaned"]=True -> counted=False, skip_reason="orphaned DHCP option set (not associated with any VPC)"
    - Resources with no IPs and not DDI -> counted=False, skip_reason="no IP addresses" (EXCEPT special cases below)
    - Special case: "lambda-function" with details["vpc_id"] non-empty -> counted=True, category="asset" even if ip_addresses is empty. VPC-attached Lambda functions are managed assets by definition; their ENIs are discovered separately via collect_enis.
    - Sets counted=True/False, category="ddi"/"ip"/"asset"/None, skip_reason on each resource
    - Note: A resource can be both a DDI object AND have IPs -- DDI takes precedence for category, but IPs still count toward IP totals

    Test cases:
    - EC2 instance with 2 IPs -> counted=True, category="asset"
    - Subnet resource -> counted=True, category="ddi"
    - EBS volume -> counted=False, category=None, skip_reason="token-free: EBS Volume"
    - S3 bucket -> counted=False, category=None, skip_reason="token-free: S3 Bucket"
    - Orphaned DHCP option set -> counted=False, skip_reason includes "orphaned"
    - VPC-associated DHCP option set -> counted=True, category="ddi"
    - Lambda function with VPC config (vpc_id set, ip_addresses=[]) -> counted=True, category="asset" (special case)
    - Lambda function without VPC config -> counted=False, skip_reason="no IP addresses" (non-VPC Lambda not discovered, but test the categorizer path)
    - Resource with no IPs and not DDI and not a special case -> counted=False

    **ip_counter.py** - count_ips(resources: list[CloudResource]) -> dict and deduplicate_ips_per_vpc(resources) -> dict:
    - Extract all private IPs and public IPs from resources
    - De-duplicate per VPC IP space: key = (vpc_id, ip_address). Same IP in different VPCs counts separately.
    - For resources without vpc_id in details, use account_id as the IP space key (global IPs like Elastic IPs)
    - deduplicate_ips_per_vpc returns: {total_unique_ips: int, per_account: {account_id: int, ...}} so that the CLI pipeline can pass per-account deduplicated IP counts to calculate_account_tokens. The Summary sheet "Active IPs" column uses per_account values.
    - count_ips returns: {private_ips: int, public_ips: int, total_unique_ips: int}
    - Both IPv4 and IPv6 count

    Test cases:
    - 2 EC2 instances in same VPC with different IPs -> both counted
    - 2 EC2 instances in different VPCs with same IP (10.0.0.1) -> both counted (different IP spaces)
    - ENI with 3 secondary IPs -> all 3 counted
    - Resource with both private and public IP -> both counted separately
    - Empty resource list -> 0 counts
    - IPv6 addresses counted alongside IPv4

    **asset_dedup.py** - fold_enis_into_parents(resources) -> list[CloudResource], exclude_managed_service_resources(resources) -> list[CloudResource], and deduplicate_assets(resources) -> list[CloudResource]:
    - fold_enis_into_parents: ENIs referenced by parent resources (via details["network_interface_ids"]) marked counted=False with skip_reason="ENI attached to parent resource". Unattached ENIs remain counted.
    - exclude_managed_service_resources: Check each resource's tags dict for AWS-managed service tags. If ANY of these tag keys are present, set counted=False with skip_reason="AWS-managed resource (tag-based exclusion)":
      - Tag keys to check: "kubernetes.io/cluster/" (prefix match -- any tag key starting with this), "eks:nodegroup-name", "aws:eks:cluster-name"
      - This preserves the legacy behavior of excluding EKS-managed EC2 nodes from managed asset counts
      - Only applies to resource types that are managed assets (ec2-instance, etc.), NOT to DDI objects
      - Helper: _is_aws_managed(tags: dict[str, str]) -> bool that checks for the presence of any managed-service tag
    - deduplicate_assets: De-duplicate by resource_id across accounts. If same resource_id appears in multiple accounts (RAM-shared), keep the one from the owning account (details["owner_id"] matches account_id), mark others as counted=False with skip_reason="shared resource counted in owning account {owner_id}".

    Test cases:
    - ENI attached to EC2 instance -> ENI marked not counted
    - Unattached ENI with IPs -> remains counted as asset
    - EC2 instance tagged with "eks:nodegroup-name" -> counted=False, skip_reason="AWS-managed resource (tag-based exclusion)"
    - EC2 instance tagged with "kubernetes.io/cluster/my-cluster" -> counted=False, skip_reason contains "AWS-managed"
    - EC2 instance tagged with "aws:eks:cluster-name" -> counted=False
    - EC2 instance with no EKS tags -> remains counted
    - VPC with EKS tags -> NOT excluded (tag-based exclusion only applies to managed asset types, not DDI)
    - Same VPC ID in two accounts (RAM-shared) -> counted once in owner account
    - Same subnet in two accounts -> counted once in owner account
    - Resources with unique IDs -> all kept

    **token_calculator.py** - calculate_tokens(ddi_count, ip_count, asset_count) -> dict:
    - Constants: DDI_PER_TOKEN=25, IPS_PER_TOKEN=13, ASSETS_PER_TOKEN=3
    - Formula: math.ceil(ddi_count/25) + math.ceil(ip_count/13) + math.ceil(asset_count/3)
    - 0 count -> 0 tokens (NOT minimum 1)
    - calculate_account_tokens(resources: list[CloudResource], deduplicated_ip_count: int | None = None) -> dict: groups resources by category, counts DDI objects and managed assets from the resource list. For IP count: if deduplicated_ip_count is provided, use it (this is the per-VPC deduplicated count from deduplicate_ips_per_vpc); otherwise fall back to summing len(r.ip_addresses) for counted resources. Returns dict with ddi_count, ip_count, asset_count, ddi_tokens, ip_tokens, asset_tokens, total_tokens.
    - calculate_provider_tokens(account_results: dict[str, dict]) -> dict: sums across accounts

    Test cases:
    - 0 DDI, 0 IPs, 0 assets -> 0 total tokens
    - 25 DDI -> 1 DDI token
    - 26 DDI -> 2 DDI tokens
    - 13 IPs -> 1 IP token
    - 14 IPs -> 2 IP tokens
    - 3 assets -> 1 asset token
    - 4 assets -> 2 asset tokens
    - 100 DDI, 200 IPs, 50 assets -> ceil(100/25) + ceil(200/13) + ceil(50/3) = 4 + 16 + 17 = 37 tokens
    - Per-account calculation with mixed resource list
  </behavior>
  <implementation>
    Follow TDD RED-GREEN-REFACTOR cycle for each module:
    1. Write test file first with all test cases (RED -- tests fail)
    2. Implement minimal code to pass all tests (GREEN)
    3. Refactor if needed (REFACTOR)

    All modules use `from __future__ import annotations`. Test files use `sys.path.insert(0, "src")` per Phase 1 pattern.

    The categorizer uses a type-to-category mapping dict for clarity:
    DDI_TYPES = {"vpc", "subnet", "route53-zone", "route53-record", "dhcp-option-set"}
    TOKEN_FREE_TYPES = {"ebs-volume": "token-free: EBS Volume", "s3-bucket": "token-free: S3 Bucket"}

    For IP counting, use ipaddress.ip_address() from stdlib to validate and canonicalize IPs. Use (vpc_id_or_account_id, ip_str) as dedup key in a set.

    For ENI folding, build a set of attached ENI IDs from parent resources' details["network_interface_ids"], then mark matching ENIs as not counted.

    For tag-based exclusion, define MANAGED_SERVICE_TAG_PREFIXES = ["kubernetes.io/cluster/"] and MANAGED_SERVICE_TAG_KEYS = {"eks:nodegroup-name", "aws:eks:cluster-name"}. Check each resource's tags: if any tag key starts with a prefix OR exactly matches a key in the set, and the resource is a managed asset type (not DDI/token-free), mark counted=False with skip_reason="AWS-managed resource (tag-based exclusion)". This must run BEFORE categorization so that excluded resources don't inflate asset counts.

    Token calculator uses math.ceil with the `if count > 0 else 0` guard per user decision (NOT legacy max(1, ...) pattern).
  </implementation>
