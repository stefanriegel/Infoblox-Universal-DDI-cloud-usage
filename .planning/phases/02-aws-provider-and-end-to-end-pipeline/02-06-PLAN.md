  <action>
    **provider.py** - Complete the discover_account() skeleton from Plan 01.

    **discover_account(self, account_id: str) -> list[CloudResource]:**
    1. Create account session: if account_id == self._current_account_id, use self._session; else assume_cross_account_role() from organizations.py. Wrap in try/except -- if role assumption fails (ClientError), raise with clear message so orchestrator captures it as an error.
    2. Get enabled regions via get_enabled_regions(account_session)
    3. For each region, create service clients and call ALL collectors:
       - ec2_client: collect_vpcs, collect_subnets, collect_enis, collect_eips, collect_nat_gateways, collect_vpn_gateways, collect_transit_gateways, collect_ebs_volumes (from token_free), collect_ec2_instances (from compute)
       - route53_client (us-east-1 only, ONCE per account, not per region per Pitfall 1): collect_route53_zones, then collect_route53_records per zone
       - dhcp: collect VPCs first, extract DhcpOptionsId set, then collect_dhcp_option_sets with that set (per Pitfall 4)
       - ecs_client + ec2_client: collect_ecs_tasks
       - eks_client: collect_eks_node_groups
       - lambda_client: collect_lambda_functions
       - elbv2_client: collect_load_balancers_v2
       - elb_client: collect_classic_load_balancers
       - rds_client: collect_rds_instances
       - elasticache_client: collect_elasticache_clusters
       - redshift_client: collect_redshift_clusters
       - s3_client (ONCE per account, not per region): collect_s3_buckets
    4. Each collector call wrapped in try/except: on failure, log warning and continue with other collectors in that region (per error handling decision: skip failed resource type in that region)
    5. Return merged list of all CloudResource instances from all regions

    Store self._current_account_id during __init__ by calling sts.get_caller_identity()["Account"].

    **cli.py** - Add the counting pipeline and output generation after orchestrator.run().

    After `resources, errors = orchestrator.run(...)`:
    1. Import and run counting pipeline:
       - from cloud_usage.counting.asset_dedup import fold_enis_into_parents, exclude_managed_service_resources, deduplicate_assets
       - from cloud_usage.counting.categorizer import categorize_resources
       - from cloud_usage.counting.ip_counter import count_ips, deduplicate_ips_per_vpc
       - from cloud_usage.counting.token_calculator import calculate_account_tokens, calculate_provider_tokens
    2. Pipeline steps (IN ORDER):
       a. fold_enis_into_parents(resources) -- mark attached ENIs before categorization
       b. exclude_managed_service_resources(resources) -- tag-based exclusion of EKS-managed nodes etc.
       c. deduplicate_assets(resources) -- dedup shared resources
       d. categorize_resources(resources) -- assign DDI/IP/Asset/skip
       e. ip_counts = deduplicate_ips_per_vpc(resources) -- count unique IPs per VPC. IMPORTANT: ip_counts returns per-VPC deduplicated totals. Pass ip_counts["total_unique_ips"] to calculate_account_tokens as the ip_count instead of summing raw ip_addresses list lengths from resources.
       f. account_summaries = {} -- build per-account token summaries: group resources by account_id, for each account call calculate_account_tokens(account_resources) using the per-VPC deduplicated IP count for that account (filter ip_counts by account). The Summary sheet "Active IPs" column must use these deduplicated counts.
       g. provider_totals = calculate_provider_tokens(account_summaries)
    3. Generate output files (only if resources found):
       - Ensure output_dir exists (os.makedirs(output_dir, exist_ok=True))
       - timestamp = scan_id (already generated earlier)
       - xlsx_path = f"{output_dir}/aws_discovery_{timestamp}.xlsx"
       - csv_path = f"{output_dir}/aws_estimator_{timestamp}.csv"
       - manifest_path = f"{output_dir}/aws_proof_{timestamp}.json"
       - Call write_xlsx_report, write_estimator_csv, write_proof_manifest
    4. Update the scan summary output to stderr:
       - Show resource counts by category (DDI, IPs, Assets, Skipped)
       - Show token totals
       - Show output file paths
    5. Handle the case where "aws" is selected: the counting/output pipeline runs for AWS resources only. When Azure/GCP are added in later phases, each provider will get its own output files.

    Also update pyproject.toml or requirements (if pyproject.toml exists) to add boto3, xlsxwriter, moto, pytest as dependencies. If no pyproject.toml exists, create a requirements.txt with: boto3, xlsxwriter, moto[all], pytest.
  </action>

      - 2 EC2 instances (one with 2 ENIs, secondary IPs) per region
      - 1 DHCP option set (VPC-associated) per region
      - 1 NAT Gateway per region
      - 1 Route53 hosted zone with 5 records (A, AAAA, CNAME, MX, NS)
      - 1 RDS instance in us-east-1
      - 1 ALB in us-east-1
      - 2 EBS volumes (token-free) per region
      - 1 S3 bucket (token-free)
    - This creates a predictable resource count for assertion

    **Test cases:**

    test_full_pipeline_single_account:
    - Create moto environment for single account
    - Instantiate AWSDiscoveryProvider with single account mode
    - Call list_accounts() -> verify returns 1 account
    - Call discover_account() -> verify returns resources of expected types
    - Run categorize_resources -> verify DDI/IP/Asset categorization is correct
    - Run count_ips -> verify IP counts match expected
    - Run calculate_account_tokens -> verify token calculation matches manual calculation
    - Example: if 2 VPCs + 4 subnets + 1 zone + 5 records + 2 DHCP = 14 DDI -> ceil(14/25)=1 DDI token
    - Verify EBS volumes and S3 buckets are in resources but counted=False

    test_output_files_generated:
    - Run full pipeline via main() with --aws flag
    - Verify XLS file exists in output dir with correct naming
    - Verify CSV file exists
    - Verify proof manifest JSON exists and is valid JSON with required fields
    - Verify proof manifest hash is consistent

    test_partial_failure_resilience:
    - Set up environment where one resource type discovery will fail (e.g., mock a specific API to raise an exception)
    - Run discover_account() -> verify it returns resources from successful collectors
    - Verify errors list contains the failure
    - Verify the scan completes (does not crash)

    test_account_filtering:
    - Test include_accounts filters correctly
    - Test exclude_accounts filters correctly

    test_dry_run_no_discovery:
    - Run main() with --aws --dry-run
    - Verify no output files are generated
    - Verify scan plan is printed to stderr

    test_token_free_resources_in_report:
    - Run full pipeline
    - Verify EBS volumes appear in resources with counted=False, skip_reason="token-free: EBS Volume"
    - Verify S3 buckets appear with counted=False, skip_reason="token-free: S3 Bucket"
    - Verify these appear in XLS detail sheet but do NOT contribute to token totals

    test_eks_managed_nodes_excluded:
    - Create EC2 instances tagged with "eks:nodegroup-name" and "kubernetes.io/cluster/test-cluster" tags
    - Run full pipeline (discovery -> dedup -> categorization -> token calculation)
    - Verify tagged EC2 instances have counted=False, skip_reason="AWS-managed resource (tag-based exclusion)"
    - Verify these excluded instances do NOT contribute to managed asset token counts
    - Verify non-tagged EC2 instances in the same environment ARE counted

    Use `sys.path.insert(0, "src")` at top. Use @mock_aws decorator on each test or on test class. Use tmpdir/tmp_path fixture for output directory to avoid polluting project directory.
