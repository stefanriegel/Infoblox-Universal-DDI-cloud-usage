  <action>
    All functions take appropriate boto3 client, account_id, region and return list[CloudResource]. Use @retry_with_backoff(max_retries=3). Always use paginators where available.

    **collect_ec2_instances(ec2_client, account_id, region):**
    - Paginate describe_instances
    - SKIP instances with State.Name == "terminated" per IP counting rules
    - resource_type="ec2-instance", resource_id=InstanceId
    - ip_addresses: THOROUGH extraction per Pitfall 2:
      1. Instance-level PrivateIpAddress and PublicIpAddress
      2. For EACH NetworkInterface: iterate PrivateIpAddresses[] for PrivateIpAddress AND Association.PublicIp on each
      3. For EACH NetworkInterface: iterate Ipv6Addresses[] for Ipv6Address
      4. De-duplicate within this resource
    - details: {instance_type: InstanceType, state: State.Name, vpc_id: VpcId, subnet_id: SubnetId, network_interface_ids: [list of NetworkInterface.NetworkInterfaceId]}
    - network_interface_ids is CRITICAL for ENI folding in asset_dedup

    **collect_ecs_tasks(ecs_client, ec2_client, account_id, region):**
    - List ECS clusters: list_clusters paginator
    - Per cluster: list_tasks paginator (desiredStatus="RUNNING" per research recommendation -- stopped tasks have released ENIs)
    - Describe tasks in batches of 100 (describe_tasks limit)
    - resource_type="ecs-task", resource_id=taskArn
    - ip_addresses: Resolve from Attachments where type=="ElasticNetworkInterface" -> get ENI ID -> describe_network_interfaces to get IPs per Pitfall 5
    - details: {cluster_arn: clusterArn, task_definition: taskDefinitionArn, launch_type: launchType, network_interface_ids: [ENI IDs from attachments]}

    **collect_eks_node_groups(eks_client, account_id, region):**
    - List EKS clusters, then list_nodegroups per cluster, then describe_nodegroup per group
    - resource_type="eks-nodegroup", resource_id=nodegroupArn
    - ip_addresses: empty (underlying EC2 instances captured by collect_ec2_instances)
    - details: {cluster_name: clusterName, nodegroup_name: nodegroupName, instance_types: instanceTypes, scaling_config: scalingConfig, status: status}
    - Per research Open Question 1: discover as metadata, count underlying EC2 instances for IPs/assets

    **collect_lambda_functions(lambda_client, account_id, region):**
    - Paginate list_functions
    - ONLY include functions with VpcConfig.VpcId set (non-empty) per Pitfall 6
    - resource_type="lambda-function", resource_id=FunctionArn
    - ip_addresses: from VpcConfig.SecurityGroupIds -> resolve ENIs? NO -- Lambda VPC ENIs are managed by AWS and may not be discoverable. Set ip_addresses based on VpcConfig subnet IDs presence (Lambda gets IPs from the subnet). Store VpcConfig.SubnetIds in details for reference.
    - details: {vpc_id: VpcConfig.VpcId, subnet_ids: VpcConfig.SubnetIds, runtime: Runtime, memory: MemorySize, network_interface_ids: list if available from VpcConfig}

    **collect_load_balancers_v2(elbv2_client, account_id, region):**
    - Paginate describe_load_balancers
    - resource_type="alb" or "nlb" based on Type field
    - resource_id=LoadBalancerArn
    - ip_addresses: for NLB with static IPs, from AvailabilityZones[].LoadBalancerAddresses[].IpAddress. For ALB, IPs are dynamic (DNS-resolved); store DNS name but don't resolve at discovery time.
    - details: {vpc_id: VpcId, dns_name: DNSName, scheme: Scheme, type: Type, state: State.Code}

    **collect_classic_load_balancers(elb_client, account_id, region):**
    - Paginate describe_load_balancers
    - resource_type="classic-elb", resource_id=LoadBalancerName
    - ip_addresses: empty (CLBs have DNS names, not static IPs)
    - details: {vpc_id: VPCId, dns_name: DNSName, scheme: Scheme}

    **Tests** using @mock_aws:
    - EC2 instance with multiple ENIs and secondary IPs (verify all IPs extracted)
    - Terminated EC2 instance skipped
    - ECS task with ENI attachment (verify IP resolution)
    - Lambda function with VPC config included, without VPC config excluded
    - ALB and NLB discovery
    - EKS node group discovery (metadata only, no IPs)

  <action>
    **database.py** - All functions use @retry_with_backoff(max_retries=3) and paginators.

    **collect_rds_instances(rds_client, account_id, region):**
    - Paginate describe_db_instances
    - resource_type="rds-instance", resource_id=DBInstanceArn
    - ip_addresses: [Endpoint.Address] if Endpoint exists (this is a DNS name, not IP -- but it resolves to private IP. Store the endpoint; IP counting will handle it differently for RDS). Actually, per IP counting rules, RDS private IPs come from the ENI in the VPC. Store Endpoint.Address in details but for ip_addresses, we need the actual IPs. RDS instances in VPCs have ENIs discoverable via describe_network_interfaces with attachment owner "amazon-rds". However, for simplicity, use the Endpoint.Address as a DNS indicator and note in details that actual IPs are on the underlying ENI (which will be discovered by collect_enis).
    - Alternative approach: set ip_addresses=[] and let the ENI discovery + folding handle IP attribution. RDS ENIs are owned by "amazon-rds" and won't fold into a parent resource, so they'll count as standalone managed assets. This is the cleaner approach.
    - details: {db_instance_class: DBInstanceClass, engine: Engine, engine_version: EngineVersion, vpc_id: DBSubnetGroup.VpcId if exists, endpoint: Endpoint.Address, port: Endpoint.Port, status: DBInstanceStatus, multi_az: MultiAZ}

    **collect_elasticache_clusters(elasticache_client, account_id, region):**
    - Paginate describe_cache_clusters (ShowCacheNodeInfo=True)
    - resource_type="elasticache-cluster", resource_id=ARN
    - ip_addresses: from CacheNodes[].Endpoint.Address (these are IPs for ElastiCache)
    - details: {cache_node_type: CacheNodeType, engine: Engine, engine_version: EngineVersion, num_cache_nodes: NumCacheNodes, status: CacheClusterStatus}

    **collect_redshift_clusters(redshift_client, account_id, region):**
    - Paginate describe_clusters
    - resource_type="redshift-cluster", resource_id=ClusterIdentifier (use ClusterNamespaceArn if available)
    - ip_addresses: [Endpoint.Address] if it's an IP, plus ClusterNodes[].PrivateIPAddress and PublicIPAddress
    - details: {node_type: NodeType, number_of_nodes: NumberOfNodes, vpc_id: VpcId, status: ClusterStatus, endpoint: Endpoint.Address}

    **token_free.py** - These resources are discovered for the audit trail but never counted toward tokens.

    **collect_ebs_volumes(ec2_client, account_id, region):**
    - Paginate describe_volumes
    - resource_type="ebs-volume", resource_id=VolumeId
    - ip_addresses: [] (EBS volumes have no IPs)
    - details: {volume_type: VolumeType, size_gb: Size, state: State, encrypted: Encrypted, attached_instance_ids: [list of Attachments[].InstanceId]}
    - These will be categorized by Plan 02 as counted=False, skip_reason="token-free: EBS Volume"

    **collect_s3_buckets(s3_client, account_id, region):**
    - list_buckets (returns all buckets, no paginator needed; S3 is global per account)
    - resource_type="s3-bucket", resource_id=bucket Name
    - region: use get_bucket_location to determine region, or set to "global" if LocationConstraint is None (us-east-1)
    - ip_addresses: [] (S3 has no IPs)
    - details: {creation_date: CreationDate}
    - Call this ONCE per account (like Route53), not per-region. Set region based on bucket location.
    - Token-free: counted=False with skip_reason="token-free: S3 Bucket"
