    **collect_azure_storage_accounts(storage_client, subscription_id: str) -> list[CloudResource]:**
    - `storage_client.storage_accounts.list()` (subscription-level).
    - resource_type="azure-storage-account". ip_addresses=[].
    - details: resource_group, kind, sku_name, access_tier.

    **collect_azure_storage_containers(storage_client, subscription_id: str) -> list[CloudResource]:**
    - For each storage account from storage_client.storage_accounts.list(), call storage_client.blob_containers.list(rg, account_name). Wrap per-account in try/except for error isolation (some accounts may have blob access disabled).
    - resource_type="azure-storage-container". ip_addresses=[].
    - resource_id = container.id or construct from account + container name.
    - details: resource_group, storage_account_name.

    **collect_azure_management_groups(mgmt_groups_client, subscription_id: str) -> list[CloudResource]:**
    - `mgmt_groups_client.management_groups.list()` (tenant-level per RESEARCH.md Open Question 1).
    - resource_type="azure-management-group". ip_addresses=[].
    - account_id = subscription_id (attribute to the subscription that ran the query).
    - region = "global".
    - details: display_name, tenant_id.

    **collect_azure_traffic_manager_profiles(trafficmanager_client, subscription_id: str) -> list[CloudResource]:**
    - `trafficmanager_client.profiles.list_by_subscription()` (subscription-level).
    - resource_type="azure-traffic-manager". ip_addresses=[].
    - details: resource_group, dns_config, traffic_routing_method.

    - `network_client.network_watchers.list_all()` (subscription-level).
    - resource_type="azure-network-watcher". ip_addresses=[].

    - resource_type="azure-nsg". ip_addresses=[].

    - details: resource_group, rule_count (len of security_rules + default_security_rules).

    **`providers/azure/provider.py`** — Wire discover_account():
    - Import all collector functions from all 5 collector modules (networking, dns, compute, hybrid_networking, database, paas, token_free).
    - discover_account(account_id) implementation:
      1. Create subscription clients via create_subscription_clients(credential, account_id).
      2. Suppress Azure SDK logging: `logging.getLogger("azure").setLevel(logging.ERROR)`.
      3. Collect all subscription-level resources using _safe_collect() for error isolation:
         - DDI: VNets, subnets (from VNets), DHCP configs (from VNets — no API call).
         - DNS: Public DNS zones, public DNS records (per zone), private DNS zones, private DNS records (per zone).
         - Networking: NICs, public IPs.
         - Compute: VMs, VMSS instances.
         - Hybrid: LBs, app gateways, firewalls, NAT gateways, private endpoints, VNet peerings (per VNet), ExpressRoute circuits, VPN gateways (per RG from VNets), Bastion hosts.
         - Database: SQL databases, Cosmos DB accounts, MySQL servers, PostgreSQL servers, Redis caches.
         - PaaS: App services, Functions, container instances, container apps, AKS clusters, API Management.
         - Token-free: VM Disks, storage accounts, storage containers (per account), management groups, traffic manager profiles, network watchers, NSGs, resource groups.
      4. Resource ordering follows dependency: VNets first (subnets/DHCP/peerings/VPN gateways depend on VNet list), DNS zones before records.
      5. Log total resources discovered per subscription.
      6. Build subscription display mapping for output formatting.

    - _safe_collect error handling additions per CONTEXT.md:
      - Detect Azure HttpResponseError with error code "MissingSubscriptionRegistration" — skip with warning.
      - Detect "AuthorizationFailed" — per-collector failure, not per-subscription. Log and continue.
      - Detect "SubscriptionNotFound" — skip entire subscription (CONTEXT.md: handle at scan time, not pre-flight).

    **`cli.py`** — Complete Azure pipeline wiring:
    - In output generation section, handle Azure provider name for output file naming: `azure_discovery_YYYY-MM-DD.xlsx` per CONTEXT.md.
    - The counting pipeline (fold_enis -> exclude_managed -> dedup -> categorize -> count_ips -> calculate_tokens) is already provider-agnostic and works for Azure resources without changes.
    - Verify the output modules handle the resource_group detail field in CloudResource.details (the XLS detail sheet should include it per CONTEXT.md "Add Azure-specific 'resource_group' column"). If the existing write_xlsx_report doesn't handle provider-specific columns, add a resource_group column extraction from details when provider is azure.

    - **Test 1: Full pipeline with mixed resources** — Create mock Azure clients returning VNets (DDI), subnets (DDI), DNS zones (DDI), DNS records (DDI), NICs (asset with IPs), public IPs (asset), VMs (asset), disks (token-free), NSGs (token-free). Run through full pipeline. Verify:

      - Asset count includes NICs + public IPs + VMs (only those with IPs or special rules)
      - Token-free resources excluded with correct skip reasons
      - Token calculation correct: DDI/25 + IPs/13 + Assets/3
    - **Test 2: Subscription filtering** — Verify include/exclude filters subscription list correctly.
    - **Test 3: Partial failure resilience** — One collector raises HttpResponseError, others succeed. Verify partial results returned with error logged.
    - **Test 4: MissingSubscriptionRegistration handled** — SQL collector returns MissingSubscriptionRegistration. Verify SQL resources empty but other resources present.
    - **Test 5: Token-free resources correctly excluded** — Verify azure-disk, azure-nsg, azure-storage-account all have counted=False after categorization.
    - **Test 6: DHCP config DDI counting** — VNet with DHCP options generates both VNet DDI + DHCP config DDI. Verify both counted.
    - **Test 7: Output file generation** — Full pipeline produces azure_discovery_*.xlsx with detail and summary sheets.
