In `src/cloud_usage/discovery/provider.py`, create the `DiscoveryProvider` abstract base class:

1. `@property @abstractmethod def provider_name(self) -> str` -- "aws", "azure", "gcp"
2. `@abstractmethod def list_accounts(self) -> list[str]` -- returns account/subscription/project IDs to scan
3. `@abstractmethod def discover_account(self, account_id: str) -> list[CloudResource]` -- discovers all resources in one account (this is the unit of work)
4. Import `CloudResource` from `cloud_usage.schema.resource`

This is the interface that Phases 2-4 will implement with cloud SDK calls. Phase 1 only defines the abstract interface.

In `src/cloud_usage/discovery/shutdown.py`, create `GracefulShutdown` class:

1. `__init__(self, checkpoint_engine: CheckpointEngine)`:
   - Store reference to checkpoint engine
   - `self._scan_state: CheckpointData | None = None`
   - `self._lock = threading.Lock()`
   - Register signal handlers: `signal.signal(signal.SIGINT, self._handler)` and `signal.signal(signal.SIGTERM, self._handler)`

2. `update_state(self, state: CheckpointData) -> None`:
   - With lock: update `self._scan_state`
   - Called by orchestrator after each account completes

3. `_handler(self, signum, frame) -> None`:
   - Write to stderr: "\nInterrupted -- saving checkpoint...\n"
   - With lock: if scan_state exists, call `self._checkpoint.save(self._scan_state)`
   - Write to stderr: "Checkpoint saved. Resume with next run.\n"
   - `sys.exit(130)` -- 128 + SIGINT convention

Per Research: "The existing signal handler is a stub that does not actually save state." This implementation captures actual scan state via the update_state method.

In `src/cloud_usage/discovery/orchestrator.py`, create `DiscoveryOrchestrator` class:

1. `__init__(self, providers: list[DiscoveryProvider], checkpoint_engine: CheckpointEngine, progress_tracker: ProgressTracker, rate_limiter: RateLimiter, max_workers: int = 20, provider_concurrency: dict[str, int] | None = None)`:
   - Store all dependencies
   - Create provider-scoped semaphores: `self._semaphores = {p.provider_name: threading.Semaphore(provider_concurrency.get(p.provider_name, 10)) for p in providers}`
   - Default concurrency per Research: AWS=10, Azure=4, GCP=8 (if provider_concurrency not provided, use these defaults)
   - Per CONTEXT.md: "Sensible defaults per provider, no user-facing concurrency knobs"

2. `_discover_account(self, provider: DiscoveryProvider, account_id: str) -> tuple[str, str, list[CloudResource], ErrorRecord | None]`:
   - Acquire provider's semaphore
   - try: call `provider.discover_account(account_id)`, return (provider_name, account_id, resources, None)
   - except: call `create_error_record()` from error taxonomy, return (provider_name, account_id, [], error_record)
   - finally: release semaphore
   - This is DISC-06: error in one worker does not crash others

3. `run(self, resumed_checkpoint: CheckpointData | None = None) -> tuple[list[CloudResource], list[ErrorRecord]]`:
   - Build work items: for each provider, call `provider.list_accounts()` to get account IDs
   - If resumed_checkpoint provided, filter out already-completed accounts
   - Register providers with progress_tracker
   - Create GracefulShutdown handler
   - Create ThreadPoolExecutor with max_workers (per Research pitfall 4: ALWAYS specify max_workers explicitly)
   - Submit all work items via `executor.submit(self._discover_account, provider, account_id)`
   - Process results via `concurrent.futures.as_completed(futures)`:
     - On success: append resources, update progress_tracker.complete_account(), update checkpoint, update shutdown handler state
     - On error: append error_record, still update progress
   - After all futures complete: call progress_tracker.finish()
   - Return (all_resources, all_errors)

4. `_build_checkpoint_data(self, ...) -> CheckpointData` -- helper to build current checkpoint state from completed accounts and resource counts.

Per user decisions:
- "Sensible defaults per provider, no user-facing concurrency knobs"
- "Rate limit backoff communicated with brief notice: 'Rate limited by AWS -- backing off 5s'"
- Inline warnings during scan per CONTEXT.md

In `src/cloud_usage/cli.py`, create the main CLI entry point:

1. `parse_args(argv: list[str] | None = None) -> argparse.Namespace`:
   - `--aws` flag: include AWS in scan
   - `--azure` flag: include Azure in scan
   - `--gcp` flag: include GCP in scan
   - `--skip-auth-check` flag: skip auth doctor (per CONTEXT.md)
   - `--output-dir` option: output directory (default: "./output")
   - `--checkpoint-ttl` option: checkpoint TTL in hours (default: 48, per RESIL-03)
   - `--no-resume` flag: ignore existing checkpoints and start fresh
   - Uses argparse with clear help text and description

2. `select_providers() -> list[str]`:
   - Interactive prompt: "Which cloud providers would you like to scan?"
   - Show numbered options: "1. AWS  2. Azure  3. GCP"
   - Accept comma-separated numbers or names: "1,3" or "aws,gcp"
   - Validate input and re-prompt on invalid selection
   - Per CONTEXT.md: "Interactive prompt at startup asks user which providers to scan"
   - Per CONTEXT.md: "the tool should feel guided, not require CLI expertise"

3. `main(argv: list[str] | None = None) -> int`:
   - Parse args
   - Determine selected providers: if any of --aws/--azure/--gcp set, use those (scripted mode); otherwise call select_providers() (interactive mode)
   - Per CONTEXT.md: "CLI flags (--aws, --azure, --gcp) bypass the interactive prompt for scripted/repeat use"
   - Set up audit logger (from cloud_usage.logging.audit)
   - If not --skip-auth-check: run AuthDoctor.check_all() for selected providers, print report
     - If some providers fail: print passing providers and ask "Continue with {passing} only? [Y/n]"
     - If all fail: print error and exit with code 1
   - Check for existing checkpoint: load via CheckpointEngine, if valid show format_resume_prompt(), ask user to confirm resume
   - If resumed: pass checkpoint data to orchestrator
   - Create DiscoveryOrchestrator with all dependencies
   - Call orchestrator.run()
   - Print final summary (resource counts, error counts, output location)
   - Return 0 on success, 1 on complete failure

4. `if __name__ == "__main__": sys.exit(main())` -- standard entry point guard.

NOTE: In Phase 1, no actual DiscoveryProvider implementations exist (those come in Phases 2-4). The CLI should handle the case where no providers are registered gracefully -- log a message like "No discovery providers configured. Provider implementations will be added in subsequent phases."

- "Failed accounts appear in final report with status 'scan failed' and error reason"
- "Every scan writes a timestamped log file to output directory automatically"
- "Proof manifest (SHA-256) is a separate file from the log -- different purposes"
