  <action>
Create `src/cloud_usage/auth/__init__.py` (empty or brief docstring).

In `src/cloud_usage/auth/validators.py`, create:

1. `AuthResult` dataclass:
   - `provider: str` -- "aws", "azure", "gcp"
   - `success: bool` -- True if auth check passed
   - `identity: str` -- e.g., "SSO profile: prod" or "Service Principal: app-123"
   - `account_count: int` -- number of accessible accounts/subscriptions/projects
   - `error_message: str | None` -- error description if failed
   - `suggestion: str | None` -- actionable fix hint (e.g., "run: aws sso login --profile prod")
   - `read_only: bool = True` -- always True, enforces AUTH-05 by design

2. `AuthValidator` abstract base class (using `abc.ABC`):
   - `@abstractmethod def validate(self) -> AuthResult` -- check credential validity AND make a lightweight API call to verify basic read access
   - `@property @abstractmethod def provider_name(self) -> str` -- returns "aws", "azure", or "gcp"

Note: Concrete validators will be implemented in Phases 2-4 when cloud SDKs are available. Phase 1 only defines the interface. Include a `MockAuthValidator` in the test file for testing.

In `src/cloud_usage/auth/doctor.py`, create `AuthDoctor` class:

1. `__init__(self, validators: dict[str, AuthValidator])` -- stores validators keyed by provider name.

2. `check_all(self, selected_providers: list[str]) -> list[AuthResult]`:
   - For each provider in selected_providers, look up validator in self._validators
   - If validator exists, call `validator.validate()` and collect result
   - If validator not registered, create a failed AuthResult with message "No validator registered for {provider}"
   - Return list of AuthResult

3. `report(self, results: list[AuthResult]) -> bool`:
   - Write to stderr (per CONTEXT.md: "Output to stderr, results to stdout")
   - For each result:
     - If success: `"  {provider}: OK ({identity}, {account_count} accounts accessible)\n"`
     - If failed: `"  {provider}: FAILED -- {error_message}\n"` followed by `"    Fix: {suggestion}\n"` if suggestion exists
   - Return True if ALL selected providers passed, False otherwise

4. `get_passing_providers(self, results: list[AuthResult]) -> list[str]`:
   - Returns list of provider names that passed validation
   - Used by caller to offer "Continue with AWS and GCP only?" when one provider fails (per CONTEXT.md)

Per user decisions:
- "Auth doctor runs automatically as first step of every scan; can be skipped with --skip-auth-check"
- "Moderate detail: pass/fail plus context (identity, account count) per selected provider"
- "Checks credential validity AND makes a lightweight API call to verify basic read access"
- "When auth fails for one provider but others pass: warn and offer to continue with passing providers only"

AUTH-05 enforcement: AuthResult always has `read_only=True`. The validator interface only verifies read access. No write API calls are ever made. This is enforced by design in the abstract interface -- concrete validators MUST only check read permissions.

In `tests/test_auth_doctor.py`, write pytest tests using a MockAuthValidator:
1. Test check_all with all providers passing
2. Test check_all with one provider failing, others passing
3. Test check_all with unregistered provider returns failed result
4. Test report returns True when all pass
5. Test report returns False when any fail
6. Test report writes to stderr (capture stderr output)
7. Test get_passing_providers returns only passing providers
8. Test AuthResult always has read_only=True (AUTH-05)

Follow project conventions: black (127 chars), Google-style docstrings, modern type hints.

Create `src/cloud_usage/discovery/__init__.py` (empty or brief docstring).

In `src/cloud_usage/discovery/progress.py`, create:

1. `ProviderProgressState` dataclass:
   - `total: int = 0` -- total accounts/subscriptions/projects for this provider
   - `completed: int = 0` -- completed so far
   - `resources: int = 0` -- total resources discovered so far

2. `ProgressTracker` class:
   - `__init__(self)`:
     - `self._providers: dict[str, ProviderProgressState] = {}`
     - `self._lock = threading.Lock()`
     - `self._is_tty: bool = hasattr(sys.stderr, "isatty") and sys.stderr.isatty()`
     - `self._total_resources: int = 0`

   - `register_provider(self, name: str, total: int) -> None`:
     - With lock: create ProviderProgressState for this provider with total set
     - Provider name should use display names: "AWS", "Azure", "GCP" (per CONTEXT.md counter format)

   - `complete_account(self, provider: str, resources_found: int) -> None`:
     - With lock: increment provider's completed count and resources count
     - Update self._total_resources
     - Call `self._render()`

   - `_render(self) -> None` (called while lock is held):
     - Build counter-line per CONTEXT.md format: `"AWS [3/12 accounts] | Azure [1/5 subscriptions] | 127 resources found so far"`
     - Use provider-appropriate labels: AWS="accounts", Azure="subscriptions", GCP="projects" (store label in registration or derive from provider name)
     - If TTY: write with `\r` prefix and flush (`sys.stderr.write(f"\r{line}  "); sys.stderr.flush()`)
     - If non-TTY (piped output): write with newline (`sys.stderr.write(f"{line}\n")`)

   - `finish(self) -> None`:
     - Write final newline to stderr (clears the carriage-return line)
     - Write final summary: "Scan complete: {total_resources} resources found across {N} providers"

   - `get_summary(self) -> dict[str, ProviderProgressState]`:
     - With lock: return copy of provider progress dict

Per user decisions in CONTEXT.md:
- Counter-line format: "AWS [3/12 accounts] | Azure [1/5 subscriptions]"
- Running totals as accounts complete: "127 resources found so far"
- Output to stderr (results to stdout) -- allows piping results while seeing progress
- No verbose mode

Allow `register_provider` to accept a custom `unit_label` parameter (default "accounts") so Azure can pass "subscriptions" and GCP can pass "projects".

6. Test thread safety: spawn 10 threads calling complete_account concurrently, verify final counts are correct
7. Test finish writes final summary

9. Test custom unit_label ("subscriptions", "projects")

Use `io.StringIO` or `unittest.mock.patch("sys.stderr")` to capture stderr output.
