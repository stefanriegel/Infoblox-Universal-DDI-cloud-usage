In `src/cloud_usage/resilience/retry.py`, create a `retry_with_backoff` decorator:

1. Parameters: `max_retries: int = 5`, `base_delay: float = 1.0`, `max_delay: float = 60.0`, `retryable_categories: set[ErrorCategory] | None = None` (defaults to `{RATE_LIMIT, NETWORK}`).

2. Implementation using `functools.wraps`:
   - On each attempt, call the wrapped function
   - On exception, call `classify_error()` from `cloud_usage.errors.taxonomy` to get the category
   - If category NOT in retryable_categories OR attempt == max_retries, re-raise
   - Otherwise apply full jitter: `sleep_time = random.uniform(0, min(max_delay, base_delay * (2 ** attempt)))`
   - Use `time.sleep(sleep_time)` for backoff
   - Log each retry attempt via `logging.getLogger(__name__)`

3. Also accept an optional `on_retry` callback `Callable[[int, Exception, float], None]` that gets called with (attempt, exception, sleep_time) for rate limiter integration.

Full jitter formula source: AWS Builders Library.

In `src/cloud_usage/resilience/rate_limiter.py`, create a `RateLimiter` class:

1. `__init__(self)` -- initializes per-provider backoff state dict, a threading.Lock for thread safety.

2. `record_rate_limit(self, provider: str, retry_after: float | None = None)` -- records that provider got rate-limited. If `retry_after` header provided, use it. Otherwise increment internal backoff counter for that provider.

3. `get_delay(self, provider: str) -> float` -- returns current recommended delay for a provider (0.0 if no backoff active, or the tracked delay). Decreases delay over time as successful calls happen.

4. `record_success(self, provider: str)` -- records successful API call, gradually reduces backoff for that provider.

5. `is_throttled(self, provider: str) -> bool` -- returns True if provider is currently in heavy throttling state (for the "scan will take longer than usual" warning per CONTEXT.md).

6. Thread-safe: all methods acquire `self._lock` before mutating state.

Per user decision: "Fully self-tuning -- adapts based on API responses (429s, Retry-After headers), no user flags" and "Start aggressive (full speed), back off when rate limits hit" and "Warn once on sustained throttling."

In `src/cloud_usage/resilience/checkpoint.py`, create:

1. `ProviderProgress` dataclass:
   - `total_accounts: int`
   - `completed_accounts: list[str]` -- IDs of completed accounts
   - `resources_found: int` -- count only, NOT the resources themselves (per Research pitfall 5)
   - `errors: list[dict]` -- serialized ErrorRecord dicts for failed accounts

2. `CheckpointData` dataclass:
   - `timestamp: str` -- ISO timestamp of last save
   - `ttl_hours: int` -- TTL for expiry (default 48)
   - `providers: dict[str, ProviderProgress]` -- per-provider progress
   - `scan_id: str` -- unique identifier for this scan run

3. `CheckpointEngine` class:
   - `__init__(self, checkpoint_dir: str = "./output/.checkpoints", ttl_hours: int = 48)`:
     - Store dir path and TTL
     - Create directory with `pathlib.Path.mkdir(parents=True, exist_ok=True)`
     - Filepath: `{checkpoint_dir}/scan_checkpoint.json`

   - `save(self, data: CheckpointData) -> None`:
     - Atomic write pattern: `tempfile.mkstemp(dir=checkpoint_dir, suffix=".tmp")`
     - Write JSON via `os.write(fd, json.dumps(asdict(data), indent=2).encode("utf-8"))`
     - `os.fsync(fd)` -- flush to disk
     - `os.close(fd)`
     - `os.replace(tmp_path, filepath)` -- atomic replace (works on POSIX AND Windows, per Research pitfall 3: use `os.replace()` not `os.rename()`)
     - On any exception: close fd if open, remove temp file, re-raise

   - `load(self) -> CheckpointData | None`:
     - If file doesn't exist, return None
     - Parse JSON, check timestamp against TTL: `datetime.now() - datetime.fromisoformat(timestamp) > timedelta(hours=ttl_hours)` -> return None (expired)
     - Reconstruct dataclass from dict
     - On corrupt JSON/missing keys, log warning and return None (don't crash)

   - `delete(self) -> None`:
     - Remove checkpoint file if exists

   - `format_resume_prompt(self, data: CheckpointData) -> str`:
     - Generate the auto-detect prompt per CONTEXT.md: "Checkpoint from {age} ago: AWS 8/12 accounts complete, Azure not started. Resume? [Y/n]"
     - Calculate age from timestamp (e.g., "2h ago", "1d ago")
     - List per-provider progress summary

Per user decisions:
- "Checkpoint files stored in project output directory (./output/.checkpoints/)"
- "Auto-detect and prompt on startup"
- "Summary of previous progress shown when checkpoint detected"
- "Expired checkpoints (48h TTL default): notify and discard"
- Store only progress metadata, NOT full resource lists (Research recommendation)

6. Test load returns None on corrupt JSON file
7. Test delete removes checkpoint file

9. Test os.replace is used (not os.rename) for cross-platform atomicity

Use `tmp_path` pytest fixture for isolated file system tests. Use `unittest.mock.patch` for time-based tests.
