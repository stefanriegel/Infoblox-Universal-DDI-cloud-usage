   - `state.delay = 0.0` (was `state.delay *= _DECAY_FACTOR` with threshold check)
   - Keep `with self._lock:` and `state = self._get_state(provider)` unchanged

**orchestrator.py — Add record_success() call in _discover_account() success path:**

1. Find `_discover_account()` method. In the `try:` block, after `resources = provider.discover_account(account_id)` and before the `return` statement, add:
   ```python
   self._rate_limiter.record_success(provider.provider_name)
   ```
2. This line must NOT appear in the `except` block. Only call record_success() when discover_account() returns without raising an exception.
3. Do NOT add record_success() inside individual collectors or providers — the orchestrator owns the rate limiter reference. This matches the existing pattern where _make_throttle_callback() in the orchestrator handles the failure side.

**Important:** The CONTEXT.md decision says "Call record_success() on every single successful API response." The practical interpretation is: call it once per successfully-completed account (when discover_account() returns without exception), not per individual collector within the account. Per-collector calling would require invasive changes to inject the rate limiter into every provider, which contradicts the existing architecture where the orchestrator owns the rate limiter.
