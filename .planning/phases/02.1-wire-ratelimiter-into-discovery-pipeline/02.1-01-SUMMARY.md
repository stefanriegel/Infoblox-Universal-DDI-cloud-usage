# Phase 2.1 Plan 01: Wire RateLimiter into Discovery Pipeline Summary

**Thread-local on_retry injection wiring RateLimiter.record_rate_limit() into retry decorator, with orchestrator get_delay() checks before each worker dispatch**

## Accomplishments
- Rate-limit errors from collectors flow through retry decorator via thread-local callback into RateLimiter.record_rate_limit()
- Orchestrator checks get_delay() before each worker dispatch, applying time.sleep(delay) when positive
- Throttle events visible in stderr during scan and summarized after completion
- Non-rate-limit transient errors (network, 503) correctly excluded from RateLimiter state
- All 454 tests pass (9 new tests added)

- `tests/test_progress.py` - 4 new tests for throttle reporting and summary

## Decisions Made
- Used thread-local `_retry_context` for runtime callback injection instead of modifying 20+ collector decorator applications (zero-change approach)
- classify_error() is called twice per retry (once by decorator, once by callback) -- acceptable since it's pure string matching with no I/O
- Non-rate-limit transient errors (network timeouts, 503s) do NOT call record_rate_limit() -- they indicate infrastructure issues, not API quota exhaustion
- Dispatch loop refactored from dict comprehension to sequential for-loop to enable delay injection between submissions
