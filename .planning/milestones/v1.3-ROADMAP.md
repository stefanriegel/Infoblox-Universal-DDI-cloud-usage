## Milestone Summary

**Key Decisions:**

- `NiosScanManager.set_progress()` stores progress server-side; GET endpoint renders HTML fragment on demand — avoids event payload size limits and keeps rendering in Python
- `progress_display.html` uses native `<progress value="N" max="6">` (determinate) rather than indeterminate spinner — concrete step count warrants determinate bar
- Formula divisors hardcoded in template (50/25/13 for NIOS, 25/13/3 for UDDI native) — values are immutable constants from UDDI spec
- Member attribution subtitle warns IP sums are lease-only (not deduped per-member) — prevents customer confusion about discrepancy with scenario totals
- Select All / Clear All use `type='button'` to prevent accidental form submission
- IIFE script at bottom of form section (scoped, no global pollution, runs after DOM ready)
- `step2_run.html` (HTMX partial swap) and `nios.html` (full-page inline block) updated independently — separate rendering paths require separate fixes

**Issues Resolved:**

- NIOS pipeline gave no progress feedback during long runs (now 6 named steps)
- Results screen showed token totals with no formula derivation (now inline)
- Member assignment step had no explanatory context (now has article + live counter)
- Wizard steps had no consistent numbering (now Step 1/2/3 throughout)

**Issues Deferred (Tech Debt):**

- NIOS running-state on page-load path shows static indeterminate bar instead of live steps (design-bounded edge case — primary HTMX wizard path satisfies PROG-01/02/03)
- REF-01: GCP 87-project production validation still pending (v1.0 carry-over, not a v1.3 requirement)

**Technical Debt Incurred:**

- None — all v1.3 requirements shipped clean
